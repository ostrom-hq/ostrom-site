## Receipt verification

A verifier following [receipt format v1](/docs/receipts/format#verify-a-receipt-yourself) refuses a receipt for one of these reasons.

| Reason | What it means | What to do |
|---|---|---|
| not a receipt | the document is not a JSON object | check that you passed the receipt itself, not a list or a wrapper around it |
| missing signature | there is no `signature` string | the receipt was never signed, or the field was removed |
| malformed signature | the field is not exactly `ed25519;kid=…;sha256=…;sig=…` (a part missing, repeated, added or moved), or `sig` is not the standard base64 of 64 bytes | the field was cut or edited; get the receipt again from its source |
| unknown algorithm | the field does not start with `ed25519` | the receipt uses a format this verifier does not know |
| unreadable key | the key you gave is not an Ed25519 public key in PEM form | pass the instance's public key, `-----BEGIN PUBLIC KEY-----` included |
| unknown key | the `kid` is not the id of the key you gave | use the public key of the instance that signed the receipt |
| digest mismatch | the content changed after signing | the receipt was edited, or a tool rewrote it: reformatting is fine, but a dropped field, a changed value or a re-encoded number is not |
| bad signature | the content matches its digest, but the signature does not match the key | the digest was forged too: treat the receipt as false |

## Exit codes of `ostrom`

Every `ostrom` command ends with one of these codes, so a script or an agent can tell a refusal from a failure. Once `ostrom claude` or `ostrom codex` has started the agent, it ends with the agent's own code.

| Code | What it means | What to do |
|---|---|---|
| 0 | done | nothing |
| 1 | the check you asked for failed: `ostrom doctor` found a ✗, `ostrom config get` found no value, the sign-in code expired | read the message above the code |
| 2 | incomplete, cancelled, or a no: a sign-in cancelled on GitHub, for example | nothing to fix: start again if you meant yes |
| 64 | bad usage: an unknown option, a value `ostrom config set` refuses, two different models named | run the command with `--help` |
| 65 | sign-in required | sign in to your Ostrom server (Coming soon: `ostrom login`) |
| 66 | not found | check the id or the folder you gave |
| 69 | the Ostrom server cannot be reached, or did not give what the command needs | check your network and the server URL, then `ostrom doctor` |
| 70 | the command is declared but not built in this version | its help ends with "(coming soon)"; it will work in a later release |
| 73 | a local file cannot be written | check the owner and permissions of the folder named, or set `OSTROM_HOME` |
| 75 | still waiting | try again later |
| 77 | refused: by your organization's policy, your role, or because you cannot approve your own request | ask an admin of your organization |
| 78 | a signature or a session package was refused | do not work around it: the package or the instance key is not the one your organization signed |
| 127 | the agent is not installed | install it from its official page, then start it again |

`ostrom doctor` checks the device in one go: the config folder, the secret store, the server, `git` and the agents installed. It exits with 1 when it finds a problem (✗), and `ostrom doctor --json` gives the same checks for a script.
