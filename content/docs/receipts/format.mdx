The receipt format is open: anyone can check a receipt without Ostrom's code. This page is the specification of version 1. Its examples run in CI, and its verifier is also run against every receipt of the format's [test vectors](#test-vectors).

## Fields

| Field | Type | Meaning |
|---|---|---|
| `id` | string | the receipt's id, starting with `rcpt_` |
| `subject` | object | what the receipt is about: `kind` (`session`, `gate`, `task`, `workflow`), `id`, and `digest`, the SHA-256 of the canonical form of the subject's record |
| `initiator` | string | who started the work |
| `agent` | string, optional | the coding agent, for example `claude-code` or `codex` |
| `model` | string, optional | the model the agent used |
| `rules` | array | the rules that applied: `id` and `digest`, the SHA-256 of the rule's exact text |
| `decisions` | array | every yes or no: `approvalId`, `by`, `at`, `result` (`approved` or `rejected`), and `selfApproved` when the person who asked was also the only approver |
| `costUsd` | number, optional | the cost in US dollars, when known |
| `package` | object, optional | the harness package in use: `version` and `digest` |
| `nodes` | array, optional | for a workflow run, what each step did: `id`, `workflowId`, `kind`, `label`, `outcome`, and optionally `detail` and `ref`; a `check` node also has `attestation`, where the check ran: `workstation_declared` (declared by the developer's workstation: its own word, not a proof), `isolated_runner` (an Ostrom runner, in an isolated session) or `ci` (the Ostrom GitHub App's check run, verified by the server). A check node without it reads as declared. Coming soon: the server does not write check nodes yet |
| `createdAt` | string | when the receipt was signed, ISO 8601 in UTC with milliseconds |
| `signature` | string | the signature field, described below |

A verifier must not drop fields it does not know: every field except `signature` is signed, known or not.

## What is signed

The signed bytes are the UTF-8 encoding of the canonical form of the receipt without its `signature` field.

The canonical form is JSON with these rules:

1. Objects: keys sorted by UTF-16 code units at every level, the default sort of JavaScript strings. No locale, no spaces, no line breaks. A key whose value is undefined is left out; an explicit `null` is written `null`.
2. Arrays: items in their order; an undefined item is written `null`.
3. Strings: exactly as JavaScript's `JSON.stringify` writes them. Quote, backslash and the control characters are escaped, control characters without a short escape as `\u00xx` in lowercase hexadecimal, a lone surrogate as `\udxxx`. Everything else is written as is, including `/` and non-ASCII text.
4. Numbers: exactly as JavaScript's `Number.prototype.toString` writes them: the shortest text that reads back as the same double, `1e+21` and above in exponent form, `-0` as `0`.
5. `true`, `false` and `null` as is.

## The signature field

```text notest="shape of the field, not a value"
ed25519;kid=KEY_ID;sha256=DIGEST;sig=SIGNATURE
```

- `ed25519`: the algorithm, pure Ed25519 as in RFC 8032, without pre-hashing.
- `kid`: the key id, the first 16 hexadecimal characters of the SHA-256 of the public key in SPKI DER form.
- `sha256`: the SHA-256 of the signed bytes, in lowercase hexadecimal.
- `sig`: the 64-byte signature of the signed bytes, in standard base64 with padding.

## Verify a receipt yourself

A receipt is valid when all of these hold, checked in this order:

1. it is a JSON object with a `signature` string;
2. the signature field is exactly `ALGORITHM;kid=KEY_ID;sha256=DIGEST;sig=SIGNATURE`, each part once and in this order, with 16 and 64 lowercase hexadecimal characters for `KEY_ID` and `DIGEST`, and 86 base64 characters then `==` for `SIGNATURE`; the algorithm is `ed25519`;
3. the public key you trust is an Ed25519 key, and the `kid` is its id;
4. the SHA-256 of the signed bytes equals `sha256`;
5. `sig` decodes to 64 bytes that encode back to the same text, and those bytes are a valid Ed25519 signature of the signed bytes under that key.

This verifier does exactly that, with Node.js 24 or later and nothing else. It is two files. The first is the canonical form, save it as `canonical.mjs`:

```js file="canonical.mjs"
// The canonical form of receipt format v1.
export function canonical(value) {
    if (value === null || typeof value !== "object") return JSON.stringify(value)
    if (Array.isArray(value)) return "[" + value.map((item) => (item === undefined ? "null" : canonical(item))).join(",") + "]"
    const keys = Object.keys(value).filter((key) => value[key] !== undefined).sort()
    return "{" + keys.map((key) => JSON.stringify(key) + ":" + canonical(value[key])).join(",") + "}"
}
```

The second is the check itself, save it as `verify-receipt.mjs`:

```js file="verify-receipt.mjs"
import {createHash, createPublicKey, verify} from "node:crypto"
import {readFileSync} from "node:fs"
import {canonical} from "./canonical.mjs"

// The signature field, exactly: algorithm, then kid, sha256 and sig, once each, in this order.
const FIELD = /^([^;]*);kid=([0-9a-f]{16});sha256=([0-9a-f]{64});sig=([A-Za-z0-9+/]{86}==)$/

function check(receipt, publicKeyPem) {
    if (receipt === null || typeof receipt !== "object" || Array.isArray(receipt)) return {problem: "not a receipt"}
    const {signature, ...body} = receipt
    if (typeof signature !== "string") return {problem: "missing signature"}
    const field = FIELD.exec(signature)
    if (field === null) return {problem: "malformed signature"}
    const [, algorithm, fieldKid, sha256, sig] = field
    if (algorithm !== "ed25519") return {problem: "unknown algorithm"}
    let key
    try {
        key = createPublicKey(publicKeyPem)
    } catch {
        return {problem: "unreadable key"}
    }
    if (key.asymmetricKeyType !== "ed25519") return {problem: "unreadable key"}
    const kid = createHash("sha256").update(key.export({type: "spki", format: "der"})).digest("hex").slice(0, 16)
    if (fieldKid !== kid) return {problem: "unknown key"}
    const signed = Buffer.from(canonical(body), "utf8")
    if (createHash("sha256").update(signed).digest("hex") !== sha256) return {problem: "digest mismatch"}
    // Re-encoding must give the same text: one signature, one spelling.
    const signatureBytes = Buffer.from(sig, "base64")
    if (signatureBytes.toString("base64") !== sig) return {problem: "malformed signature"}
    if (!verify(null, signed, key, signatureBytes)) return {problem: "bad signature"}
    return {kid}
}

const [receiptPath, keyPath] = process.argv.slice(2)
const receipt = JSON.parse(readFileSync(receiptPath, "utf8"))
const {problem, kid} = check(receipt, readFileSync(keyPath, "utf8"))
if (problem === undefined) {
    console.log("valid: " + receipt.id + ", signed by key " + kid)
} else {
    console.log("invalid: " + problem)
    process.exitCode = 1
}
```

The receipt above was signed with the public test key of the format's vectors. It derives from a published seed, so it signs test vectors and nothing else; never trust it for real receipts. Save it as `test-key.pem`:

```text file="test-key.pem"
-----BEGIN PUBLIC KEY-----
MCowBQYDK2VwAyEAFaTHPoIFP1zbbrrHDBIDpfCW9zXjiXCkuGwP9LU8puM=
-----END PUBLIC KEY-----
```

Check the receipt:

```sh test
node verify-receipt.mjs receipt.json test-key.pem
```

```text output
valid: rcpt_487602be-d073-43c6-83b9-c4163084b042, signed by key b918e282a924dda0
```

Now change who said yes, and check again:

```sh test exit="1"
sed 's/"rev-b"/"rev-c"/' receipt.json > forged.json
node verify-receipt.mjs forged.json test-key.pem
```

```text output
invalid: digest mismatch
```

A key other than the one that signed the receipt is refused before any signature check:

```sh test exit="1"
node -e 'const {generateKeyPairSync} = require("node:crypto"); process.stdout.write(generateKeyPairSync("ed25519").publicKey.export({type: "spki", format: "pem"}))' > other-key.pem
node verify-receipt.mjs receipt.json other-key.pem
```

```text output
invalid: unknown key
```

## Test vectors

The vectors are the reference for any implementation: the test key, canonical-form cases (non-ASCII text, `U+2028`, control characters, astral keys, `-0`, `1e21`, `0.1 + 0.2`, `5e-324`, a lone surrogate), and signed receipts of every subject kind. An implementation is correct when it produces the same canonical bytes and accepts every vector receipt. The verifier on this page is tested against them, and so is the mobile app's.

## Versioning

A change to the canonical form or to the signed bytes is a new format version. Receipts signed under version 1 stay verifiable with the rules on this page.
